# 猫眼榜单订阅（MaoyanPro）

> [← 返回插件一览](../../README.md#插件一览) · 版本 v1.1.1 · 目录 `plugins.v3/maoyanpro`

按配置的榜单类型、平台和排名数量获取猫眼数据，识别媒体后添加订阅；
同时把抓取结果落成**榜单快照**，通过对外接口提供给 App、脚本与宿主推荐页。
**订阅与推荐页相互独立**：订阅勾了多少、甚至完全关掉订阅，推荐页/榜单接口都按自己的条数设置展示。

## 安装

MoviePilot →「设定 → 插件市场 → 添加市场」，填入
`https://github.com/KingNuoNuo/MoviePilot-Plugins`，保存后搜索「**猫眼榜单订阅**」安装并启用。

本地部署也可把 `plugins.v3/maoyanpro` 整个目录拷贝到 MoviePilot 的插件目录
（容器内通常为 `/app/app/plugins/`，以你的实际部署为准），重启容器即可。

## 配置说明

订阅类型把**电影**与**剧集**分开设置，两组互不牵连。剧集只抓猫眼原生的
**电视剧+网剧综合榜**（官网的热度口径），不再单列电视剧榜 / 网剧榜；综艺同属剧集
大类（只是榜单独立），类型勾选也并入「剧集订阅类型」，只把**条数**留在下面单独配置：

| 配置 | 说明 |
| --- | --- |
| 电影订阅类型 | 电影票房榜单、网络电影榜单 |
| 剧集订阅类型 | 剧集综合榜单（电视剧+网剧）、综艺热度榜单 |
| 电影/剧集/综艺榜单订阅条数 | 各榜自动订阅的条数，可选项含 **0**（综艺条数独立于剧集条数） |
| 电影/剧集/综艺榜单推荐条数 | 榜单快照 / 推荐页 / 榜单接口展示的条数，可选项含 **0** |
| 腾讯视频 / 爱奇艺 / 芒果TV / 优酷订阅条数 | 各平台细分榜的订阅条数，可选项含 **0** |
| 开放榜单接口 / 接入推荐页数据源 | 对外接口与宿主推荐页数据源的开关 |

**条数即开关**，不再需要单独的开关：

- **订阅条数 = 0** —— 不订阅该榜（仍会抓取并更新快照，推荐页照常展示）
- **推荐条数 = 0** —— 推荐页与榜单接口不展示该榜（订阅不受影响）
- **两者都为 0** —— 该榜完全不抓取
- 每榜实际抓取 `max(订阅条数, 推荐条数)` 条，订阅只取其中前「订阅条数」条

平台细分榜只服务自动订阅，**不写入榜单快照/推荐页**，避免推荐页里出现一堆
「剧集热度榜单（腾讯视频）」这类重复栏目。

## 对外接口

注册在宿主 `/api/v1/plugin/MaoyanPro` 前缀下，默认使用宿主的 **API 令牌**认证
（`X-API-KEY` 头或 `?apikey=` 查询参数），也可用网页登录态调用。

| 接口 | 返回 | 说明 |
| --- | --- | --- |
| `GET /rank` | `Response[MaoyanProSnapshot]` | 榜单快照，含名次、类型、平台、票房/热度、媒体身份与海报 |
| `GET /rank-list` | `Response[List[MediaInfo]]` | 推荐页 / 浏览页数据源，声明 `page` 参数 |
| `GET` `POST /refresh` | `MaoyanRefreshResult` | 立即触发一次抓取与订阅 |

`/rank` 支持三个可选参数：

- `board_type`：`movie`（电影票房）、`web-movie`（网络电影）、`web-all`（剧集综合榜：
  电视剧+网络剧）、`zongyi`（综艺热度）
- `board`：榜单名关键字，如 `腾讯视频`
- `limit`：每个榜单最多返回的条目数，用于限制响应体大小

```bash
curl "http://<MP>:3000/api/v1/plugin/MaoyanPro/rank?apikey=<API_TOKEN>&limit=5"
curl "http://<MP>:3000/api/v1/plugin/MaoyanPro/rank?apikey=<API_TOKEN>&board_type=web-heat"
curl -X POST "http://<MP>:3000/api/v1/plugin/MaoyanPro/refresh?apikey=<API_TOKEN>"
```

响应为宿主统一三段式 `{ success, message, data }`，`data.boards[].items[]` 即榜单条目。
**未识别到媒体的条目仍会返回**（身份字段为空），便于调用方先渲染榜单。

## 接入宿主推荐页（可选）

配置中打开「接入推荐页数据源」后，插件通过 `ChainEventType.RecommendSource`
把已配置的榜单注册到宿主推荐页：电影票房进「电影」分类，
剧集综合 / 综艺热度进「电视剧」分类。注册是**叠加**到事件数据，
不会影响其它插件的数据源。订阅总开关关闭时推荐源照常有效。

## 快照与兜底

- 每次刷新把榜单落成插件数据 `snapshot`（含逐条回填的媒体来源、ID、海报、简介、年份）。
- **抓取全失败时保留上一次快照**，避免异常时段接口返回空数据。
- 升级后尚未跑过刷新时，`/rank` 回退到订阅流水并在 `message` 中注明，保证接口始终可用。
- `/rank-list` 会过滤掉没有媒体身份的条目，因为它们无法被宿主识别为媒体。

## 异常处理

- 上映信息为空或为未知文案时，使用未知年份继续识别；明确上映日期、已上映天数和首日文案按对应规则解析。
- 剧集综合榜（不传 `seriesType`，官网返回电视剧+网络剧综合榜）与综艺（`seriesType=2`）使用官网当前热度接口，按北京时间查询当天榜单，保留各平台筛选。每轮刷新复用一个官网浏览器会话，由页面脚本处理请求校验。
- 浏览器启动或页面加载失败时，继续尝试无 Cookie 请求未处理榜单；热度接口需要页面校验，此时可能仍返回 403。失败来源会明确记录，不影响其他来源继续处理。
- 一个来源请求失败、返回非 JSON 或响应结构异常时，记录来源地址并继续其他榜单。
- 榜单内的无效条目、单条媒体识别或订阅异常只影响该条目，日志标明来源排名或媒体标题。
- 跳过坏条目后不补取配置排名范围之外的内容；保留跨平台剧集去重，成功订阅的条目仍保存历史。

出现部分失败后，可从日志中的来源地址、排名和媒体标题定位问题；“刷新完成”表示本轮遍历结束，不代表所有来源都成功。
